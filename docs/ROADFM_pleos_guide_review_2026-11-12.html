2. 🔴 심사·배포 차단 위험

P1 · 반려

자동 재생 금지 규정과 기획·프로토타입이 충돌

Music/Audio 가이드 §개발 정책

가이드 요건

  • 프로필 변경·연결 시 자동 재생 금지
  • 재생은 사용자의 명시적 동작 또는 시스템 재개 요청으로만

현재 상태

  • ROADFM_deepgreen.html:90 "오디오 가이드 자동 재생" 토글 기본 ON, 문구 "새로운 지역의 이야기가 준비되면 재생"
  • API 매핑 16행 "출발하기 → 오디오 자동 재생", 21행 autoAudio
  • 기획서 시나리오 6 "이동 중 위치에 맞는 오디오가 재생된다"

해결방안

  1. 재생 상태 머신을 명시: IDLE / PLAYING / PAUSED_BY_USER / PAUSED_BY_FOCUS. 위치 트리거는 PLAYING일 때만 큐 뒤에 추가하고, IDLE·PAUSED_BY_USER에서는 어떤 경우에도 재생을 시작하지 않습니다.
  2. 토글을 "이어서 듣기 — 다음 지역 이야기를 재생 목록에 자동 추가"로 이름 변경, 기본값 OFF. 필드명은 autoAudio → continuousQueue.
  3. "출발하기" 버튼은 재생을 시작하지 않고 "이야기 듣기" 버튼을 따로 둡니다(또는 버튼명을 "출발하고 이야기 듣기"로 해서 명시적 동작임을 분명히).
  4. 시동·프로필 변경 시에는 마지막 항목을 준비(prepare)만 하고 재생하지 않습니다. 재개는 Media3 onPlaybackResumption()으로 오는 시스템 요청에서만 합니다.
  5. 기획서 시나리오 6을 "사용자가 시작한 재생 세션 동안, 다음 지역 이야기가 목록에 이어진다"로 수정합니다.
Pleos 확인: 사용자 세션 중 위치 기반 큐 추가가 '자동 재생'에 해당하지 않는지
P2 · 반려

카테고리 적합성·하위 카테고리 미정의

Music/Audio 가이드 §카테고리 · 앱 카테고리 가이드

가이드 요건

  • 오디오 재생이 핵심 기능이어야 함. 보조 기능이면 "즉시 반려"
  • 하위 카테고리(Music/Podcast/Audiobook/Radio) 필수. 미정의 시 반려
  • 모든 콘텐츠 단일 리스트 혼합 노출 제한
  • 매니페스트 appCategory(game/audio/video)와 마켓 서비스 카테고리는 별개

현재 상태

  • 경로 추천(F-03), 방문 기록(F-04), 퀴즈·스탬프(F-05), 경유지 추가(F-01) 등 비오디오 기능 비중이 큼
  • 경유지 설정·위치 기반 정보는 Mobility Services, 지도는 Maps/Navigation의 허용 예시에 해당
  • "FM"을 내세우지만 실제 콘텐츠는 사전 생성 TTS 에피소드

해결방안

  1. 마켓 카테고리 Music/Audio, 매니페스트 android:appCategory="audio"로 정합니다. 소개 문구를 "위치 기반 오디오 여행 채널"로, 핵심 가치를 듣는 경험으로 서술하고, F-03·F-04·F-05는 "청취 경험을 보조하는 주차 중 기능"으로 표현합니다.
  2. 하위 카테고리는 Podcast 권장(지역·주제별 에피소드 구조와 일치). Radio로 가려면 연속 편성 채널 개념이 있어야 설득력이 있습니다.
  3. 브라우즈 트리를 나눕니다: 루트 → [이 경로의 이야기] [지역별] [주제별(자연·미식·역사)] [최근 들은 이야기].
  4. 경로 지도는 앱에서 빼거나 주차 중 화면에만 둡니다(P9).
Pleos 확인: 비오디오 기능 비중이 이 정도일 때 Music/Audio 심사 통과 가능한지, 카테고리 복수 지정 가능 여부
P3 · 배포 제외

MediaBrowserService/MediaLibraryService 미구현, 매니페스트 누락

Music/Audio 가이드 §필수 구현

가이드 요건

  • MBS 미구현 시 차량 탑재·배포 대상에서 제외 가능
  • MediaSession으로 재생 상태·제어 제공
  • android:appCategory="audio", androidx.car.app.launchable=true meta-data

현재 상태

  • apps/vehicle에는 MainActivity 하나뿐
  • app/build.gradle.kts에 Media3 의존성 없음
  • AndroidManifest.xml에 서비스·FGS 권한·카테고리 선언 없음 (targetSdk 35라 FGS 타입 필수)

해결방안

  1. androidx.media3:media3-session, media3-exoplayer 추가.
  2. com.roadfm.car.playback.RoadFmPlaybackService : MediaLibraryService 생성. Media3는 레거시 MediaBrowserService 인터페이스도 함께 노출하므로 두 액션을 모두 intent-filter에 등록합니다.
  3. 매니페스트에 FOREGROUND_SERVICE, FOREGROUND_SERVICE_MEDIA_PLAYBACK, POST_NOTIFICATIONS, foregroundServiceType="mediaPlayback", appCategory, launchable meta-data 추가. 골격은 6장.
Pleos 확인: MediaSessionCompat 기준 요건을 Media3 레거시 호환 계층으로 충족하는지
P4 · 기능 불가

DO 미선언 시 주행 중 앱 사용 불가

지역별 주행 규제 정책 · 주행 규제 개발 가이드

가이드 요건

  • DO 미선언 앱: Parking 사용 가능 / Drive 사용 불가
  • DO 선언 앱: CarUxRestrictionsManager.registerListener() → onUxRestrictionsChanged()로 받은 getActiveRestrictions()에 따라 앱이 직접 기능 축소
  • Pleos 문서에 DO 매니페스트 선언 방법은 없음

현재 상태

  • 기획서 5장: 홈 "주행 중 간소화된 재생 컨트롤", NOW PLAYING "주행 제한 준수"를 전제
  • DO 선언·CarUxRestrictions 연동 코드 없음

해결방안

권장안 A (미디어 센터 위임) — 주행 중 재생 UI는 미디어 센터가 담당하고, MainActivity는 DO를 선언하지 않습니다. 주행 중에는 시스템이 앱 화면을 막고, 사용자는 미디어 센터·스티어링 키·음성으로만 조작합니다. 구현 비용이 가장 작습니다.

대안 B (전용 DO 화면) — 주행용 DrivingNowPlayingActivity만 DO로 선언하고 제목·지역·진행·재생/일시정지만 표시. CarUxRestrictions 리스너로 LIMIT_STRING_LENGTH·LIMIT_CONTENT 등을 반영합니다. 나머지 화면은 DO 미선언 유지.

Pleos 확인: DO 선언 방식(AAOS 표준 distractionOptimized meta-data가 동일하게 적용되는지), 써드파티 앱의 DO 선언 허용 조건
P5 · 반려

스티어링 휠 키: 미디어 ID·검색 기반 재생

Music/Audio 가이드 §스티어링 휠 키

가이드 요건

  • 최소: 재생, 일시정지, 정지, 미디어 ID 기반 재생, 검색 기반 재생
  • 가능하면 이전/다음 트랙

현재 상태

  • GET /audio?placeId= — 트랙 고유 ID 체계 없음(매핑 문서도 불일치로 표시)
  • 오디오 콘텐츠 검색 API 없음(/places/search는 목적지 검색)

해결방안

  1. 백엔드에 스토리 리소스 신설: GET /audio/stories/{storyId}, GET /audio/stories?regionId=&theme=&routeId=, GET /audio/stories/search?q=. storyId는 재생성되어도 바뀌지 않는 고정 키. 스키마 변경은 Flyway 마이그레이션으로.
  2. 서비스에서 mediaId = "story:{storyId}", 폴더는 "region:{id}", "theme:{id}", "recent"로 규칙화.
  3. Media3 콜백: 미디어 ID 재생은 onAddMediaItems()에서 ID → URI 해석, 검색 재생은 onSearch()/onGetSearchResult() 구현. 이전/다음은 큐 기반으로 기본 지원.

P7

Gleo AI 음성 연동(필수)

Music/Audio 가이드 §Gleo AI

기획서는 STT를 후순위로 두었지만, 가이드는 Gleo Interface 구현 또는 Media3 표준 API 준수 중 하나를 요구합니다. 곡(이야기) 검색 음성 기능은 MediaLibraryService의 검색 구현이 필수이며 MediaSession만으로는 제한됩니다.

해결방안

  1. 1단계 — 방식 2(Media3 표준): P3·P5 구현으로 자동 충족. "강릉 이야기 틀어줘" → onSearch → 스토리 검색 API.
  2. 2단계 — 방식 1(Gleo Interface): 핵심 기능 3~5개 추가. 후보: "근처 이야기 들려줘", "이 장소 다시 들려줘", "다음 지역 이야기 미리 듣기", "방문 기록 켜줘". 주차 전용 기능(퀴즈 등)은 제외.
P8

"정차" ≠ "Parking", 동승자 예외 근거 없음

지역별 주행 규제 정책

주행 규제는 속도·기어·브레이크 신호로 판정합니다. 신호 대기(D단 정차)는 Drive로 판정될 가능성이 높습니다. 기획서의 "정차 중"(경로 비교·장소 상세·퀴즈·기록 편집·설정)은 대부분 실제로는 쓸 수 없는 시점을 가리키게 됩니다. F-05의 "동승자 환경" 예외는 어느 Pleos 문서에도 없습니다.

해결방안

  1. 기획서 전체에서 "정차 중"을 "주차(P) 상태"로 치환하고 시연 시나리오 4번도 수정.
  2. F-05의 "또는 플랫폼이 허용하는 동승자 환경" 문구 삭제(근거 확보 전까지).
  3. UX 흐름 재검토: 경로·장소 선택은 출발 전 주차 상태에서 끝내도록 유도하고, 주행 중 새 추천은 오디오로만 안내 → 다음 주차 때 확인하는 "나중에 보기" 목록에 쌓기.
Pleos 확인: Parking/Drive 판정 기준, 한국 지역의 정책 적용 열
P9

prototype2 오디오 화면에 지도·waveform

앱 카테고리 · 주행 안전 설계

ROADFM_deepgreen.html:63-65 page-audio에 경로 안내 지도 SVG와 waveform이 있습니다. Music/Audio 카테고리의 주행 중 허용 예시는 앨범아트·단순 조작뿐이며, 지도는 Maps/Navigation 카테고리 예시입니다. 설계 가이드는 주행 중 움직이는 이미지·자동 애니메이션 최소화를 요구합니다.

해결방안

  1. 주행 상태 오디오 화면은 정적 지역 아트워크 + 제목 + 지역명 + 진행 바 + 재생 컨트롤로 축소.
  2. 지도·waveform은 주차 상태 화면으로 이동하거나 제거.
  3. 시연 영상에서 "주행 중 화면"과 "주차 중 화면"을 구분해 보여주면 규제 이해도를 어필할 수 있습니다.

(내비 안내)		볼륨 감쇄 권장. 덕킹 중 pause는 정책 의도에 맞게결정 필요: 말소리 콘텐츠라 겹치면 내용 손실 → 일시정지 + 3초 되감기 권장
AUDIOFOCUS_GAIN정상 재생PAUSED_BY_FOCUS였을 때만 재개, PAUSED_BY_USER면 유지

해결방안

  1. AudioAttributes: usage = USAGE_MEDIA, contentType = SPEECH → CarAudioContext MUSIC. 내비보다 우선하려고 ASSISTANCE_NAVIGATION_GUIDANCE를 쓰면 안 됩니다.
  2. ExoPlayer setAudioAttributes(attrs, handleAudioFocus = true)로 포커스를 맡기면 SPEECH 콘텐츠는 덕킹 대신 일시정지로 처리됩니다. 영구 상실은 onPlayWhenReadyChanged(reason = PLAY_WHEN_READY_CHANGE_REASON_AUDIO_FOCUS_LOSS)에서 stop()으로 처리.
  3. Pleos가 덕킹을 요구하면 SPEECH 대신 기본 contentType을 쓰거나, 포커스를 직접 관리(AudioFocusRequest)하도록 전환.
  4. 포커스 로그: 포커스 이벤트·재생 상태 전이·duck 적용/해제를 태그 RoadFmFocus로 기록(가이드 로그 필수 항목 참고).
Pleos 확인: 음성 콘텐츠 앱의 CAN_DUCK 시 일시정지 허용 여부
P11

서비스 생명주기

Music/Audio 가이드 §서비스 라이프사이클
  • onCreate()에서 startService()로 Started 상태 유지(bind만 하면 onTaskRemoved() 미수신 가능)
  • onStartCommand()·재생 시점 startForeground()
  • onTaskRemoved(): 내부 정지 → stopMedia() → stopSelf() → super.onTaskRemoved()
  • 쓰리핑거 동작 시 onStop() → ExoPlayer.stop()

해결방안

  1. Media3 MediaSessionService는 재생 시 foreground 전환과 알림을 자동 처리합니다. 가이드의 startService() 요건은 onCreate()에서 자기 자신을 startService(Intent(this, RoadFmPlaybackService::class.java))로 한 번 호출해 충족합니다.
  2. onTaskRemoved()는 재생 여부와 무관하게 정지·해제 후 stopSelf(), 마지막에 super 호출(골격 참고).
  3. 컨트롤러의 stop 명령은 Media3 기본 동작이 player.stop()이므로 별도 오버라이드 불필요. 에뮬레이터에서 쓰리핑거 동작으로 검증.

기능별 제한 플래그 대응

지역별 주행 규제 정책 · 주행 안전 설계

주행 중 제한되는 대용량 텍스트(LIMIT_CONTENT, LIMIT_STRING_LENGTH), 설정(NO_SETUP), 키보드(NO_KEYBOARD) 등을 5장 매트릭스로 정리했습니다.

  3. 목적지 검색은 키보드보다 NaviHelper로 받은 내비 목적지 → 최근 목적지 → 음성 순으로 우선.
  4. 위치·방문 기록 동의 화면은 주차 중에만(북미·유럽 확장 시에도 안전).

방문 추정(F-04)의 백그라운드 위치 수집

Music/Audio 가이드 §라이프사이클 (파생 이슈)

앱을 스와이프로 종료하면 미디어 서비스는 정지·종료해야 합니다. 체류 판정을 미디어 서비스 안에 얹으면 그때 함께 중단됩니다.

해결방안

  1. 방문 추정은 별도 컴포넌트로 분리하고, 사용자가 자동 기록을 켠 여정 진행 중에만 동작.

  3. Pleos 위치 SDK 가용성 확인 결과에 맞춰 구현 범위 결정(기획서 리스크 표 519행).

class RoadFmPlaybackService : MediaLibraryService() {
    private var session: MediaLibrarySession? = null

    override fun onCreate() {
        super.onCreate()
        // 가이드: bind 만으로는 onTaskRemoved 를 못 받을 수 있어 Started 상태 유지
        startService(Intent(this, RoadFmPlaybackService::class.java))

        val attrs = AudioAttributes.Builder()
            .setUsage(C.USAGE_MEDIA)
            .setContentType(C.AUDIO_CONTENT_TYPE_SPEECH) // 덕킹 대신 일시정지 (P10 결정에 따라 조정)
            .build()
        val player = ExoPlayer.Builder(this)
            .setAudioAttributes(attrs, /* handleAudioFocus = */ true)
            .setHandleAudioBecomingNoisy(true)
            .build()
        player.addListener(object : Player.Listener {
            override fun onPlayWhenReadyChanged(playWhenReady: Boolean, reason: Int) {
                // AUDIOFOCUS_LOSS(영구 상실) → 정지, 세션이 활성으로 남지 않게
                if (reason == Player.PLAY_WHEN_READY_CHANGE_REASON_AUDIO_FOCUS_LOSS) player.stop()
            }
        })
        session = MediaLibrarySession.Builder(this, player, LibraryCallback(/* repo */)).build()
    }

    override fun onGetSession(controller: MediaSession.ControllerInfo) = session

    override fun onTaskRemoved(rootIntent: Intent?) {
        session?.player?.run { stop(); clearMediaItems() } // 내부 정지 로직 먼저
        stopSelf()
        super.onTaskRemoved(rootIntent)                    // super 는 마지막
    }

    override fun onDestroy() {
        session?.run { player.release(); release() }
        session = null
        super.onDestroy()
    }
}

// LibraryCallback 구현 대상
//  onGetLibraryRoot   → 루트: 이 경로의 이야기 / 지역별 / 주제별 / 최근
//  onGetChildren      → 폴더별 story 목록 (단일 혼합 리스트 금지)
//  onGetItem          → "story:{storyId}" 단건
//  onSearch / onGetSearchResult → GET /audio/stories/search?q=  (Gleo·검색 재생)
//  onAddMediaItems    → mediaId → 스트림/캐시 URI 해석 (미디어 ID 재생)
//  onPlaybackResumption → 시스템 재개 요청 시에만 마지막 항목 반환 (자동 재생 아님)

8. Pleos 문의 목록

  1. 비오디오 기능(경로 추천·방문 기록·퀴즈)을 포함한 앱이 Music/Audio 카테고리 심사를 통과할 수 있는지, 마켓 카테고리 복수 지정이 가능한지
  2. 하위 카테고리로 Podcast 지정이 적절한지(사전 생성 TTS 지역 이야기)
  3. 사용자가 시작한 세션 중 위치 기반 큐 추가가 자동 재생 금지에 해당하지 않는지
  4. 미디어 센터 연동 문서·API 제공 범위
  5. 스티어링 휠 키 요건(MediaSessionCompat 기준)을 Media3 레거시 호환으로 충족하는지
  6. 써드파티 앱의 DO 선언 방식·허용 조건
  7. 한국 주행 규제 정책 적용 열과 Parking/Drive 판정 기준
  8. 음성 콘텐츠 앱의 CAN_DUCK 시 일시정지 허용 여부
  9. 동승자 화면·동승자 모드 예외 존재 여부

문의 채널: Pleos Playground 콘솔 또는 문서에 안내된 partnership 창구.
